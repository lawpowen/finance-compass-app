# UI 参考基线

## 事实来源

`artifacts/ui-reference/` 中的 29 张用户确认截图是 0.8.0 界面的唯一视觉基线。实现应保持真实本地账户、交易和预算数值，因此金额和名称可以与截图示例不同；页面结构、信息层级、色彩、间距、图标语义和交互入口必须与对应截图一致。

主检查宽度为 390 逻辑像素。长页面在同一宽度下滚动检查，不通过压缩整页来适配桌面窗口。

## 视觉与交互契约

- 背景为近黑深青渐变；主强调色为青绿色，支出、负债和主操作为橙色。
- 六个主页面使用固定底部导航：总览、账户、交易、预算、报表、设置。
- 交易页右下角保留同尺寸闪电与加号；新增消费只从交易流程进入，信用卡详情不提供新增消费按钮。
- 交易页月份下方使用一张宽选中卡加两张窄卡展示“实际消费”“实际现金”“信用/贷款”，点击卡片实时切换下方指标；卡片下保留页点、“已发生/包含预计”分段、两项口径解释和账户/类型/类别筛选。选中卡使用青绿色描边及深青底色，“实际现金”和支出使用橙色主金额；本月及未来月份选中实际现金时副标题显示“需准备现金”。三种口径不把交易列表分成三个互相隐藏的页面。
- 交易行、搜索结果和信用卡账单明细行必须可点击进入新版交易编辑器；编辑保存保留原交易 ID。编辑页面底部提供橙色描边“删除交易”入口，点击后以确认对话框说明不可撤销和余额恢复，取消时保留编辑页面。交易行尾部保留旧版三点菜单，顺序为编辑、复用新增、保存模板、保存周期、分隔线、删除；菜单不取代整行点击。未来月份右箭头可用，进入未来月份默认展示“即将发生”。
- 新增交易和周期计划的生成入口都提供 1–12 个月直接选择，不固定为三个月；所有月份统一继承用户选择的“已发生”或“预计”状态。
- 账户、类型、类别筛选均可多选：同组取任一、组间同时满足，未勾选表示全部；账户筛选包含转账目标账户。底部面板的取消不提交，应用后同时更新交易列表、实际消费和信用/贷款口径；高级筛选按钮打开同一面板，不再进入旧交易页。“实际现金”的需准备总额保持全月资金需求，并明确说明不随下方筛选缩小。未来贷款月供按完整付款额进入已知现金流出。
- 本月及未来月份的“实际现金”主金额为已知现金流出加尚未安排的当月到期信用卡/贷款，不再显示独立资金需求大卡。选中后副标题显示“需准备现金”，两项解释显示“已知流出/尚未安排”，下一行紧凑显示到期信用、到期贷款、已包含及“不重复计算”；历史月份同名卡显示实际现金支出。
- 全应用遵守“可见可点即有真实行为”：导航箭头只出现在有处理逻辑的行；直接输入框不使用导航箭头；未实现的附件、Google 登录、系统通知调度和系统主题跟随必须标为计划中并禁用。逐页结果见 [全应用交互审计](INTERACTION_AUDIT.md)。
- 账户页“统计截止”整行可点击，打开从最早账本月份到本月的连续月份列表。选择历史月份后，分组汇总和详情统一按月末计算，详情显示只读历史提示并提供“返回本月”；历史模式不显示编辑、还款、生成预计交易或录入市值入口。
- 类别管理的收入/支出分组整行可展开和折叠，箭头必须随状态上下切换；账户与类别输入框、禁用 Google 登录及只读主题预览不显示右箭头。
- 账户页头部旗标和净资产摘要下方的“资产目标”卡都可进入目标页。目标页必须提供新增入口；非空目标卡可编辑和删除，并显示当前总资产趋势、目标金额、进度、剩余金额或首次达成日期。信用卡和贷款负债不得扣减目标进度。“当前总资产”、趋势和进度截止到今天日终，本月稍后日期的已录入实际收入不会提前显示；期初余额即已达标的目标只显示“已达成”而不带日期。
- 总览“未来 30 天”是可点击范围选择器，提供 7、30、60、90 天；选择后预计余额、结束日期、横轴日期和曲线必须一起更新。
- 信用卡账单时间线显示动态年月；本期和未出账列表分别使用完整账期边界，不能展示其他月份/账期的消费。记录还款使用与贷款一致的两步操作：先选择同币种现金还款账户，再确认或调整还款金额；历史截止状态不显示可用还款入口。
- 信用卡“查看账单”打开历史月份底部列表，每项展示账期、还款日和金额；选择后主金额、时间线及明细同时切换到该期，历史模式显示“返回本期”，实时额度条不随历史选择改变。
- 信用卡账户行的“当前欠款”和详情额度使用包含未来日期但状态为已发生的分期，排除所有预计记录；本期账单文案和时间线仍只反映截至今天所属账期的记录。
- 金额必须支持真实数据长度，使用弹性布局或等比缩放，不允许在 390 像素宽度出现 Flutter overflow 标记。
- 交易金额输入使用带符号数字键盘并允许显示 `0.00` 与负号；删除按钮和保存按钮均需保持至少 52 逻辑像素高的触控区域。
- 转账类型在主金额下方显示第二个“转入金额”区块及目标币种。未选目标账户时提示先选择；同币种自动同步且转入栏只读；跨币种显示参考汇率、允许编辑实际到账金额，并提供“重新换算”恢复当前设置汇率。转出/转入账户选择仍在基本信息区保留，两个入口必须驱动同一状态。
- 预算主页面顶部以“分类基础预算 ÷ 当月已分配预算”计算占比，按预算额从高到低展示最多五个分类；超过五个分类时，余量仅保留为未标名区段，不能用一个醒目的“其他”替代已确认分类。实际支出使用实色，预计支出使用斜纹，未使用额度保持底色可见。
- 外观页使用可水平拖动的主题卡片轮播，露出相邻卡片以提示可滑动。拖动或点击卡片只切换预览；点击相邻卡片会选中该主题并将其移到中间。只有点击“设为当前主题”才写入并应用主题，完成后按钮显示“当前正在使用”。选择器触发的翻页动画经过的中间卡片不会覆盖所选预览。卡片提供主题名、选中状态和点击预览的读屏语义。总览/交易预览切换同样不得改写用户设置。
- 关于与支持页使用可滚动单列布局，在 390 像素宽度完整显示版本、隐私边界、GitHub 三个链接、自愿支持说明和二维码；二维码保持原比例并提供语义标签，不能把支持描述为购买、订阅或功能解锁。
- 预算编辑页在生效月份下明确说明“从该月起持续生效”；修改到新月份时保留旧月份规则，页面标题和说明在 390 像素宽度不得溢出。
- 报表为单页：顶部期间选择同时更新净资产变化与趋势、实际现金流和支出分类排行；当前资产构成、投资未实现盈亏和本月预算标注各自时点，不随所选期间变化。现金流只计实际现金进出，信用卡刷卡不在此重复计出，现金还信用卡和贷款按整笔付款显示。支出分类明确标为交易发生口径，信用卡消费按消费日计入；图表外提供金额与文字标签，不仅靠颜色表达正负或类别。旧报表详情入口及误导性健康信号箭头已移除。
- 快速模板管理页的右侧拖动手柄必须可用；用户可在全部模板之间调整顺序，并把“其他模板”拖入前五。排序保存后，编号 1–5 与交易页闪电快捷面板的五个模板保持一致。右下角加号的新建流程在交易草稿返回后打开模板命名框；保存名称后应正常返回模板列表并显示新模板，不得出现红屏或残留对话框。
- 信用卡资料缺失时，编辑界面建议额度 `MYR 10,000`、结算日 `12`、还款日 `28`；仅在用户保存后写入，迁移不会改写旧资料。
- 贷款编辑页分开显示合同开始日与开始记账日期，并显示合同金额、利率、年限、还款日、还款方式、可选开始记账余额及月供预览；等额本息和平息贷款显示可选“银行核定月供”，等额本金隐藏该字段。中途建账说明明确提示过去期数不会生成交易。新建完整贷款后进入详情并弹出“生成预计还款交易？”；用户可选择同币种还款账户为每期生成一笔显示完整金额的“贷款月供”，也可暂不生成。贷款详情展示当前剩余贷款、月供、剩余利息、剩余还款和待记录期数列表，并提供精确数量的生成/补齐入口；390 像素宽度下主按钮只写“记录第 N 期还款”，金额保留在摘要与确认框，避免按钮溢出。
- 贷款预计按钮必须写出实际缺口：“生成 N 期预计交易”“补齐 N 期预计交易”或禁用状态“预计交易已补齐”，不得使用含糊的“全部”。删除已记录月供后，主按钮和计划行必须即时退回被删除的最早期次。
- Google 登录与跨设备同步、银行品牌图标仍为计划能力；贷款的浮动利率、手续费、罚息、部分/提前还款重算不得暗示已经可用。

## 未来已确定账单交互

信用卡“查看账单”月份列表在存在未来 `actual`/`settled` 记录时，先按近到远显示并标记“已确定”，随后为本期及往期；每项展示账期、还款日和可校对的原始账单额。账单月份按结算日前一天命名，例如 8 月 1 日结算显示为“7 月账单”。选择后主金额、时间线及明细同时切换到该期，非本期模式显示“返回本期”，实时额度条不随月份选择改变。已还款月份仍显示原始账单额，而不是零；顶部紧凑按钮使用“已确定”，以保持 390 像素基准宽度无溢出。

## 变更检查

修改 `features/**` 或 `core/theme/**` 时，至少对照受影响页面参考图，并在 `design-qa.md` 记录相同宽度、相同状态的配对检查结果。数据模型或日期规则变化还需同步更新 `DATA_DESIGN.md` 和 `SYSTEM_REQUIREMENTS.md`。
