# UI 参考基线

## 页内说明

标题旁的问号用于查看统计口径、较长的字段说明和设备设置指引。点击或用键盘激活后可阅读说明，按 Esc 或点「知道了」即可关闭。金额、状态、错误与导入覆盖等关键确认仍出现在操作位置。

## 三主题视觉基线与黑白极简默认值

默认与历史回退外观使用「黑白极简（`monochrome`）」：暖白纸面（`#F7F7F4`）、纯白卡片（`#FFFFFF`）、细微投影（`0x0A000000`）、近黑文字（`#141413`）、等宽数字（`tabularFigures`）与严格灰阶圆环，并仅对财务极性/告警引入通过 WCAG AA 对比度校验的语义墨水色（收入 `#1E6B47`、支出 `#B83227`、警示 `#94540F`）。

通过 `FinanceThemePalette`、`AppThemeStyle.selectableStyles` 与设备本地偏好 `app_meta['theme_style']`，本机额外提供**多巴胺（`dopamine`：薄荷 `#63D4C0`、杏橙 `#F4AD79`、薰衣草 `#BCB3EF`、灰蓝 `#78929A` 构成 5 色分类圆环与高辨识卡片，主操作按钮选用杏橙配合深墨前景）**与**苹果液态玻璃（`liquidGlass`：三段冰蓝浅海渐变 `#DDF0FC → #CDE3F7 → #D1EFE9` 叠加 `CompassBackdropLayer` 静态多点珍珠极光光晕、半透毛玻璃卡片 `cardSurface: 0x94FFFFFF`、`cardBlurSigma: 12`、`dockBlurSigma: 20`、`dockSurfaceAlpha: 0.58`，以及带悬浮白色晶体镜片指示器的 Dock 玻璃胶囊）**。设置页「外观与主题」支持点击三套主题实时局部预览，取消或退出保留原主题，点击「应用主题」持久化写入成功后再刷新全应用并保留历史值与未知值向黑白极简的自动归一。桌面预算保留金额、占比、进度及结转。手机预算总览显示分类占比与剩余，进入分类详情可查看实际、预计和结转。

液态玻璃交互件（仅当 `palette.glassHighlightColor != null` 生效，黑白极简与多巴胺不变）：`compassGlassHighlight(intensity:)` 绘制顶部柔光带、左上曲面镜面月牙、右下青/鸢尾色焦散反光、Fresnel 渐变描边与内斜面明暗；彩色填充（主按钮 0.55、悬浮气泡 0.7）降低内部高光强度以保持白字对比度。`CompassPrimaryButton` 启用且非描边时使用 `#1E8AE8 → resolvedColor → 深海` 纵向液态渐变与柔和同色辉光（自定义 `color` 时以其提亮色起始），`FilledButton` 透明承载墨水、焦点与语义，禁用态保持原样；`CompassActionBubble` 带白色玻璃描边与同色辉光；`CompassStatusBadge` 为磨砂珍珠胶囊；记账页 `_BasisCard` 与 `_StatusSwitch` 改为半透明玻璃卡/轨道与白冰选中镜片；对话框与底部面板为 96% 冰面加白色高光描边（模态遮罩上不做模糊以保持文字清晰），输入框使用 62% 白色填充。背景极光新增珍珠主光并采用 5 段缓降衰减抑制色带，背景画布与页面内容以 `RepaintBoundary` 分层隔离；所有模糊阴影与 `BackdropFilter` 仍受 `!compassIsCpuSoftwareWeb` 门控。

## 圆环图与首屏载入

按已确认的 A、B 示意使用圆角 14 逻辑像素的卡片。圆环直径 146，环宽为直径的 16%，中央显示总额，底部图例列出名称、金额（总览/报表）与比例；黑白极简使用灰阶圆环，多巴胺与液态玻璃则与 `palette.donutColors` 共用同源调色板并配清晰的分隔描边。桌面预算盘点显示总占比、实际、预计与剩余数字，以及当月剩余天数与日均可用参考。总览及报表按账户汇总现金、投资和退休正余额。负债单列，沿用账户页的信用卡与贷款口径，按卡计算欠款以保留其他卡的实际债务。

首屏数据尚未准备好时显示圆形与卡片骨架，数据准备后短暂淡入，启用减少动效时直接显示。记账后的后台上传不占用首屏载入状态。总览预测折线 `CompassAreaChart` 与报表净现金流 `_NetFlowLine` 支持指针悬停及触控搓擦实时气泡与极值引导标签，支出分类在桌面以横向比例条结合对齐表格呈现，并支持页内展开全部分类。

## 桌面与手机布局

桌面与手机都使用居中的浮动胶囊导航。六个入口仅展示纯图标并隐藏常驻底栏文字，当前页图标高亮，选中胶囊底色读取 `palette.selectedSurface` 回退至 `surfaceAlt`。鼠标或指针悬停至对应图标时，上方弹出带毛玻璃/对比色调的悬浮文字标签，同时对应图标放大并向上轻盈浮起（邻近图标同步微幅联动，启用减少动效时跳过动画）。页面内容可从胶囊后方和两侧滚过，毛玻璃只在胶囊轮廓内（`dockBlurSigma` / `dockSurfaceAlpha` / `glassHighlightColor`）。列表尾部留出滚动余量，让最后一条记录可以移到胶囊上方。胶囊避开底部系统安全区。

从总览点 KPI 卡片或负债/预算状态会切换到或打开对应的主标签。各标签的详情页仍在工作区内保留胶囊导航，再次轻触当前已激活的底部标签可回退到该标签根页面；换页后切回可回到原详情或编辑页面。

内容区达到 960 逻辑像素时采用桌面排版。主工作区居中，最大宽度为 1240，两侧留出统一页边距；详情页居中并限制最大宽度 840。窄窗口（390 / 320px）保留单列自适应与每日小计/横向防溢出保护。

报表的现金流、分类、趋势提示及分享按账本本位币格式化，金额汇总口径沿用账本设置。桌面报表将净资产和实际现金流的趋势卡片并排对齐。分类、金额和占比在下方表格中使用固定阅读顺序。期间控制绑定历史区块，月末区块使用自己的截止日期。布局研究参考成熟账本的图表分组、日期筛选和分类明细呈现。[Actual Budget](https://actualbudget.org/docs/tour/reports/) · [Monarch](https://help.monarch.com/hc/en-us/articles/21846787088916-Using-Reports) · [YNAB](https://support.ynab.com/en_us/spending-breakdown-H1H7YxmD0)

总览、资产目标、预算汇总和交易汇总使用本位币。账户余额、额度与估值使用账户币种。单笔交易、模板和周期规则使用交易原币。换算预览读取已保存的主辅币种与汇率，具体符号或币种代码由显示偏好决定。

设计核对使用 Next Level Builder 的 [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) 中 Flutter 的布局建议，以及 Paul Bakaus 的 [Impeccable Layout](https://github.com/pbakaus/impeccable/blob/main/skill/reference/layout.md) 对内容优先级、间距和响应式断点的检查。

项目按 Awwwards 权重评审。设计占 40%，检查对齐、排版和视觉层级。易用性占 30%，检查任务路径、导航连续性、键盘和触控。创意占 20%，检查 Dock 与账本图表的视觉辨识度。内容占 10%，检查金额、日期、状态与文案是否清楚。[Awwwards 评审维度](https://www.awwwards.com/about-evaluation/)

PWA 另检查触控、视口和离线行为。[Mobile Excellence 指南](https://www.awwwards.com/mobile-excellence-guidelines.pdf)

## 分类与旧账本导入

分类编辑从下拉选单选择上级。也可选择顶层分类。导入预览会显示旧备份中需要修复的上级关系。无法确定的对应关系仅在确认导入后移除，该分类及所属交易和预算会继续保留。

## 金额键盘

点金额栏或欄内键盘按钮打开应用内键盘，交易表单的金额标题也可点击。数字从分位输入，`1134 → 11.34`，`150 → 1.50`。支持 `+`、`−`、`×`、`÷`、正负切换、清空和退格。每个运算数也按分位输入，`200` 表示 `2.00`。按「完成」将金额回填，保存表单后入账。修改后关闭键盘会请用户确认是否放弃。

预算桌面明细保留实际与预计分栏及读屏标签。手机版总览仅显示分类、预算分配占比和剩余，超预算时显示「超出」。点击分类可查看实际、预计和结转。

同一键盘用于交易、可编辑的跨币种转入金额、账户金额、还款、预算、资产目标和资产估值。利率、汇率、百分比和期数使用普通数字输入。

保存交易时，如有必填项缺失或金额无效，表单保留输入并定位相应提示。桌面支持 Ctrl+Enter 或 Cmd+Enter 保存，金额键盘和输入法仍处理自身的确认操作。

同步交易保存后可继续操作。后台同步一般没有全屏提示，待上传状态可在设置查看；需要解决真实冲突或重新登录时才打开恢复界面。

## 事实来源

`artifacts/ui-reference/` 中的 29 张用户确认截图是 0.8.0 界面的唯一视觉基线。实现应保持真实本地账户、交易和预算数值，因此金额和名称可以与截图示例不同；页面结构、信息层级、色彩、间距、图标语义和交互入口必须与对应截图一致。

主检查宽度为 390 逻辑像素。长页面在同一宽度下滚动检查，不通过压缩整页来适配桌面窗口。

## 视觉与交互契约

- 背景为近黑深青渐变；主强调色为青绿色，支出、负债和主操作为橙色。
- 底部浮动导航包含总览、账户、交易、预算、报表和设置。
- 交易页右下角保留同尺寸闪电与加号；新增消费只从交易流程进入，信用卡详情不提供新增消费按钮。
- 交易页月份下方使用一张宽选中卡加两张窄卡展示“实际消费”“实际现金”“信用/贷款”，点击卡片实时切换下方指标；卡片下保留页点、“已发生/包含预计”分段、两项口径解释和账户/类型/类别筛选。选中卡使用青绿色描边及深青底色，“实际现金”和支出使用橙色主金额；本月及未来月份选中实际现金时副标题显示“需准备现金”。三种口径不把交易列表分成三个互相隐藏的页面。
- 交易行、搜索结果和信用卡账单明细行必须可点击进入新版交易编辑器；编辑保存保留原交易 ID。编辑页面底部提供橙色描边“删除交易”入口，点击后以确认对话框说明不可撤销和余额恢复，取消时保留编辑页面。交易行尾部保留旧版三点菜单，顺序为编辑、复用新增、保存模板、保存周期、分隔线、删除；菜单不取代整行点击。未来月份右箭头可用，进入未来月份默认展示“即将发生”。
- 新增交易和周期计划的生成入口都提供 1–12 个月直接选择，不固定为三个月；所有月份统一继承用户选择的“已发生”或“预计”状态。
- 账户、类型、类别筛选均可多选：同组取任一、组间同时满足，未勾选表示全部；账户筛选包含转账目标账户。底部面板的取消不提交，应用后同时更新交易列表、实际消费和信用/贷款口径；高级筛选按钮打开同一面板，不再进入旧交易页。“实际现金”的需准备总额保持全月资金需求，并明确说明不随下方筛选缩小。未来贷款月供按完整付款额进入已知现金流出。
- 本月及未来月份的“实际现金”主金额为已知现金流出加尚未安排的当月到期信用卡/贷款，不再显示独立资金需求大卡。选中后副标题显示“需准备现金”，两项解释显示“已知流出/尚未安排”，下一行紧凑显示到期信用、到期贷款、已包含及“不重复计算”；历史月份同名卡显示实际现金支出。
- 全应用遵守“可见可点即有真实行为”：导航箭头只出现在有处理逻辑的行；直接输入框不使用导航箭头；未实现的附件、Google 登录、系统通知调度和系统主题跟随必须标为计划中并禁用。逐页结果见 [全应用交互审计](INTERACTION_AUDIT.md)。
- 账户页“统计截止”整行可点击，打开从最早账本月份到本月的连续月份列表。选择历史月份后，分组汇总和详情统一按月末计算，详情显示只读历史提示并提供“返回本月”；历史模式不显示编辑、还款、生成预计交易或录入市值入口。
- 类别管理的收入/支出分组整行可展开和折叠，箭头必须随状态上下切换；账户与类别输入框、禁用 Google 登录及只读主题预览不显示右箭头。
- 账户页头部旗标和净资产摘要下方的“资产目标”卡都可进入目标页。目标页必须提供新增入口；非空目标卡可编辑和删除，并显示当前总资产趋势、目标金额、进度、剩余金额或首次达成日期。信用卡和贷款负债不得扣减目标进度。“当前总资产”、趋势和进度截止到今天日终，本月稍后日期的已录入实际收入不会提前显示；期初余额即已达标的目标只显示“已达成”而不带日期。
- 总览“未来 30 天”是可点击范围选择器，提供 7、30、60、90 天；选择后预计余额、结束日期、横轴日期和曲线必须一起更新。
- 信用卡账单时间线显示动态年月；本期和未出账列表分别使用完整账期边界，不能展示其他月份/账期的消费。记录还款使用与贷款一致的两步操作：先选择同币种现金还款账户，再确认或调整还款金额；历史截止状态不显示可用还款入口。
- 信用卡“查看账单”打开历史月份底部列表，每项展示账期、还款日和金额；选择后主金额、时间线及明细同时切换到该期，历史模式显示“返回本期”，实时额度条不随历史选择改变。
- 信用卡账户行的“当前欠款”和详情额度使用包含未来日期但状态为已发生的分期，排除所有预计记录；本期账单文案和时间线仍只反映截至今天所属账期的记录。信用分组标题的“负债总额”等于各卡当前欠款之和；溢缴卡的当前欠款显示为 0.00（不显示贷方金额）。只有远期已确定分期的卡显示“尚未出账”，详情主金额标签为“当前欠款”。布局、组件尺寸与配色不变。
- 账户页“净资产”加回信用卡溢缴贷方余额（本月读当前余额、历史月份读月末截止余额的正数部分），而“总资产”“负债”“负债总额”与信用卡行金额不含溢缴；例如溢缴 80、欠款 470 时负债显示 470、净资产显示 −390。
- 信用卡账户设置（`04-credit-card-settings.png` 对应的 `AccountFormDialog`）“额度与余额”分区的余额行标签为“信用卡余额”，其下常显小字“欠款填负数，溢缴款填正数”；输入框使用带符号数字键盘，显示并保存已存储的有符号值，不自动取反。输入 `NaN`/`Infinity` 时行内提示“请输入有效金额”，不关闭页面。
- 信用卡“记录信用卡还款”对话框只接受有限正数；`NaN`、`Infinity`、0 或负数显示“请输入大于 0 的还款金额。”，对话框保持打开且不新增交易。
- 金额必须支持真实数据长度，使用弹性布局或等比缩放，不允许在 390 像素宽度出现 Flutter overflow 标记。
- 交易金额输入使用应用内固定两位小数键盘并允许显示 `0.00` 与负号；删除按钮和保存按钮均需保持至少 52 逻辑像素高的触控区域。
- 转账类型在主金额下方显示第二个“转入金额”区块及目标币种。未选目标账户时提示先选择；同币种自动同步且转入栏只读；跨币种显示参考汇率、允许编辑实际到账金额，并提供“重新换算”恢复当前设置汇率。转出/转入账户选择仍在基本信息区保留，两个入口必须驱动同一状态。
- 预算主页面以“分类基础预算 ÷ 当月已分配预算”计算圆环占比，依预算额显示前三类，其余合计。桌面明细保留各列，手机总览仅显示占比和剩余。
- 关于与支持页使用可滚动单列布局，在 390 像素宽度完整显示版本、隐私边界、GitHub 三个链接、自愿支持说明和二维码；二维码保持原比例并提供语义标签，不能把支持描述为购买、订阅或功能解锁。
- 预算编辑页在生效月份下明确说明“从该月起持续生效”；修改到新月份时保留旧月份规则，页面标题和说明在 390 像素宽度不得溢出。
- 报表为单页：顶部期间选择同时更新净资产变化与趋势、实际现金流和支出分类排行；当前资产构成、投资未实现盈亏和本月预算标注各自时点，不随所选期间变化。现金流只计实际现金进出，信用卡刷卡不在此重复计出，现金还信用卡和贷款按整笔付款显示。支出分类明确标为交易发生口径，信用卡消费按消费日计入；图表外提供金额与文字标签，不仅靠颜色表达正负或类别。旧报表详情入口及误导性健康信号箭头已移除。
- 快速模板管理页的右侧拖动手柄必须可用；用户可在全部模板之间调整顺序，并把“其他模板”拖入前五。排序保存后，编号 1–5 与交易页闪电快捷面板的五个模板保持一致。右下角加号的新建流程在交易草稿返回后打开模板命名框；保存名称后应正常返回模板列表并显示新模板，不得出现红屏或残留对话框。
- 信用卡资料缺失时，编辑界面建议额度 `MYR 10,000`、结算日 `12`、还款日 `28`；仅在用户保存后写入，迁移不会改写旧资料。
- 贷款编辑页分开显示合同开始日与开始记账日期，并显示合同金额、利率、年限、还款日、还款方式、可选开始记账余额及月供预览；等额本息和平息贷款显示可选“银行核定月供”，等额本金隐藏该字段。中途建账说明明确提示过去期数不会生成交易。新建完整贷款后进入详情并弹出“生成预计还款交易？”；用户可选择同币种还款账户为每期生成一笔显示完整金额的“贷款月供”，也可暂不生成。贷款详情展示当前剩余贷款、月供、剩余利息、剩余还款和待记录期数列表，并提供精确数量的生成/补齐入口；390 像素宽度下主按钮只写“记录第 N 期还款”，金额保留在摘要与确认框，避免按钮溢出。
- 贷款预计按钮必须写出实际缺口：“生成 N 期预计交易”“补齐 N 期预计交易”或禁用状态“预计交易已补齐”，不得使用含糊的“全部”。删除已记录月供后，主按钮和计划行必须即时退回被删除的最早期次。
- Google 登录与跨设备同步、银行品牌图标仍为计划能力；贷款的浮动利率、手续费、罚息、部分/提前还款重算不得暗示已经可用。

## 未来已确定账单交互

信用卡“查看账单”月份列表在存在未来 `actual`/`settled` 记录时，先按近到远显示并标记“已确定”，随后为本期及往期；每项展示账期、还款日和可校对的原始账单额。账单月份按结算日前一天命名，例如 8 月 1 日结算显示为“7 月账单”。选择后主金额、时间线及明细同时切换到该期，非本期模式显示“返回本期”，实时额度条不随月份选择改变。已还款月份仍显示原始账单额，而不是零；顶部紧凑按钮使用“已确定”，以保持 390 像素基准宽度无溢出。

## 变更检查

修改 `features/**` 或 `core/theme/**` 时，至少对照受影响页面参考图，并在 `design-qa.md` 记录相同宽度、相同状态的配对检查结果。数据模型或日期规则变化还需同步更新 `DATA_DESIGN.md` 和 `SYSTEM_REQUIREMENTS.md`。
