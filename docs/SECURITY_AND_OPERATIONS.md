# 安全与运维

## 当前安全模型

- 财务资料默认只存放在应用文档目录的 SQLite 数据库。
- 默认本地版无需用户认证，账本只写当前设备。本项目另有可选的[账号同步部署](SYNC_HOSTING.md)，仅在其模式内把账本写入 Homelab。
- AI 网关和系统分享是用户主动触发的外部数据流。
- 完整 JSON 可能包含敏感财务资料，用户应自行保护导出文件。
- 导入与导出只在用户主动选择文件或保存位置后执行；应用不申请后台云上传，也不自动发送完整备份给外部 AI。
- “请开发者喝杯咖啡”只展示仓库内静态 Touch 'n Go QR 图片，不接入支付 SDK、不读取付款结果、不改变功能权限。发布前必须核对收款人 `LAW PO WEN` 与资产哈希；二维码异常替换按安全事件处理。
- 静态自托管 Web 的 Drift WASM SQLite 只写入访问站点的浏览器 OPFS/IndexedDB；同一用户在两台设备、两个浏览器、不同域名或端口会得到不同账本。清理浏览器站点数据可能使该账本不可恢复。
- 账号同步版使用独立 HTTPS origin、HttpOnly/Secure/SameSite 会话、密码派生哈希、请求来源校验、注册登录限流和独立服务端 SQLite。会话和账本按账号隔离。API 禁止缓存，服务端口只由同源反向代理访问。备份卷请按财务资料管理。
- 自托管 Compose 默认绑定 `127.0.0.1:8080`。公网或家庭网访问必须经管理员控制的 HTTPS 反向代理和访问控制；示例 Caddy Basic Auth 使用 bcrypt 环境变量。不得直接暴露 8080、使用 HTTP 记账，或把 Basic Auth 明文/哈希、JSON、SQLite、私钥或反向代理环境文件提交到仓库。
- Web 数据库运行时属于供应链敏感资产。`web/sqlite3.wasm` 必须匹配锁定的 `sqlite3 2.9.4` Dart package；`tool/sqlite3_wasm.lock` 固定官方 release URL、`730989` bytes 和 SHA-256 `922A76B182B6AF69B030C8E2FDD3283ECC8E827248B20E4B1F3F3DB170B52117`，构建与 Dockerfile 会拒绝不匹配内容。不得用“latest”下载替换它。
- 自托管 Web 不向第三方发起请求：CanvasKit 随站点提供，Roboto/Noto Sans SC 回退字体从同源 `fonts/` 加载，Caddy CSP 的 `connect-src 'self'` 会拒绝引擎对 `fonts.gstatic.com` 的任何其他回退字体请求（相应字符显示为方框，不会泄露访问者 IP）。`web/fonts/` 与 `sqlite3.wasm` 一样属于供应链资产：每个文件的 SHA-256 固定在 `web/fonts/SHA256SUMS`，构建脚本校验失败即中止。

## 升级与故障恢复

- 原生 v1–v8 升级前，应用通过 SQLite 在线备份将同一读取快照（含 WAL 中已提交的记录）复制为独立的 `finance_app.sqlite`，并从副本生成逐表 `snapshot.json`。只有版本、完整性和外键检查通过，两份文件才一起发布到 `finance_compass_backups/pre_v9_*`。备份失败时保留原库供重试。回滚时关闭全部账本进程，另存当前库及关联日志，再把恢复点的 SQLite 文件作为一个整体恢复；旧实例的 WAL/SHM 不能拼接到这个副本。较早版本的恢复点按其生成时的文件组恢复。
- 数据库升级和完整导入使用事务。
- 完整导入前验证文件非空、格式版本、字段类型、ID 唯一性及实体引用，原生端在私有文档目录生成 JSON 恢复点。Web 端通过主动下载保留旧账本。事务提交前执行 SQLite 完整性与外键检查。导入失败时保留原数据库状态并显示可读错误。
- Android 导出使用系统文档选择器直接写入并关闭输出流；应用只在字节非空且原生写入没有抛错时报告成功。取消保存不产生成功提示，旧的 0 KB 文件不会被当作可恢复备份。
- 启动后执行 SQLite 完整性与外键检查。
- 恢复原始数据库时，应用必须停止，并同时处理 SQLite、WAL 和 SHM 文件。
- Web 版本更新前必须在每个使用的浏览器下载完整 JSON。Service Worker 只缓存静态壳文件，入口和 Worker 采用 no-cache 响应以避免升级长期卡在旧壳；清缓存、切换域名或浏览器 profile 前先下载 JSON。Web 导入没有隐藏的服务器恢复点，必须由用户明确保留导出文件。
- 手工账单对账前必须停止当前应用并使用 SQLite 在线备份接口生成一致性副本；修复应写入明确交易、重算物化余额并执行 `integrity_check` 与 `foreign_key_check`，不得只覆盖账户余额掩盖缺失流水。

## Google Play 与身份计划

Android 包版本为 `0.10.1+45`（2026-09-29 以 `v0.10.1` 公开发布；签名证书 SHA-256 与 `v0.10.0` 相同，可覆盖升级，但尚未在 Android 真机验证覆盖升级）。正式版应用 ID 为 `com.financecompass.app`，使用本机独立发布密钥；Gradle 在缺少 `android/key.properties` 时拒绝 Release 构建，不允许静默退回 Debug 签名。密钥和密码文件被 Git 忽略，必须离线备份。内部测试 Debug 版继续使用 `com.financecompass.app.debug` 和独立数据目录，避免覆盖正式版。Google 登录、Google Play 隐私政策和数据安全表仍属于上架前工作；公开 GitHub 侧载不代表已经上架 Google Play。

周期规则保存后只在本地生成未来预计交易，不改变账户实际余额。贷款的全期预计交易必须由用户在提示框或详情页明确触发，并在选择同币种还款账户及确认期数和金额后批量写入完整月供；记录实际还款时替换对应期次的预计月供。打开贷款详情会自动把本应用旧版生成的 `planned` 本金/利息组合合并为一笔月供，不改写实际历史记录，也不改写中途建账以前的月份。该流程不新增网络、后台任务或系统权限。

信用账户快捷还款同样需要用户明确触发，只展示同币种 `ReportGroup.cash` 来源，并在用户确认金额后写入本地实际转账。它不读取银行凭据、不自动扣款，也不新增账户权限或网络调用；跨币种场景不在该快捷流程内静默换算。

货币格式和通知偏好保存在 `app_meta`。原生及本地模式使用应用内提醒。同步模式的系统推送须在设备上主动授权，明确绑定当前账号，服务器只向通过端点校验的浏览器推送服务发送。退出登录会尝试同时撤销当前设备的本地和服务端订阅，其他设备继续按各自权限接收。Worker 展示详情前再次核对会话账号与订阅端点，旧账号的清理失败也不会授权新账号查看其到期通知。离线、会话过期和订阅撤销的运行边界见[系统提醒](SYNC_HOSTING.md#系统提醒)。服务端备份包含订阅及 VAPID 私钥，应按敏感资料保护。

公开 GitHub 分发与私人测试资料必须隔离。公开 Release 只上传签名 APK、Windows 安装器、便携 ZIP 和 SHA-256；完整 JSON、SQLite、银行来源资料、`key.properties` 与 JKS 永不公开。完整流程见[公开发布、测试版与数据恢复作业](RELEASE_WORKFLOW.md)。

外部 AI 分析只在用户主动按下分享按钮后发送提示词；应用不会自动附加完整备份。提示词兼容分析摘要 JSON 与完整备份 JSON，并要求接收方严格区分已发生、未来已确定和预计记录。完整 JSON 仍可能包含账户名称、商户、备注和金额，用户必须在外部 AI App 中自行决定是否上传；提示词优化不改变这一敏感数据边界。
