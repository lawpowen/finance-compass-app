# 系统需求

## 目标与范围

Finance Compass 是本地优先的个人财务应用，用于管理账户、交易、预算、资产和财务报表。目标平台包括 Android、Windows、iOS、macOS 和 Linux；Google Play 上架是后续发布目标。

## 当前功能

- 自托管 Web/PWA：用户可将静态 Web 服务部署到 Ubuntu、Windows 或 macOS 的 Docker 主机，并从 iOS Safari、Android Chrome 或桌面浏览器以 HTTPS 打开。Web 端必须支持 manifest、standalone 显示、静态离线外壳和 Drift WASM 浏览器持久化；每个浏览器/origin 独立存储，不能描述为云同步或服务端账本。清除浏览器网站数据前必须导出 JSON。
- Web 自托管默认只监听 `127.0.0.1:8080`；要让其他设备访问，管理员必须自行配置 HTTPS 与访问控制。应用不提供用户注册、服务端认证、远程 API、服务端备份或跨设备同步。
- 设置页“关于与支持”必须提供当前版本、公开 GitHub 源码、最新下载和问题报告入口，并展示用户提供的 Touch 'n Go 静态支持二维码。支持必须明确为自愿行为，不解锁额外功能、不形成服务权益；付款前提示确认收款人 `LAW PO WEN`
- 公开版本必须同时提供已签名 Android APK、Windows x64 安装器、完整便携 ZIP 和 SHA-256 校验文件；Windows 单独 EXE 不构成可运行分发包
- 多账户、多币种和跨币种转账；新版交易表单必须同时显示转出金额和转入金额。同币种目标自动使用相同数值且不可独立修改，跨币种目标按“货币、汇率与显示”设置中的当前汇率自动换算，并允许用户以银行实际到账金额覆盖换算结果
- 收入、支出、转账、调整以及计划/实际状态；交易列表、搜索结果和信用卡账单明细必须可进入同一新版编辑器修改原记录。点击交易整行直接编辑，三点菜单提供编辑、复用新增、保存模板、保存周期和删除，且所有入口必须执行真实数据操作。交易金额允许有限的正数、零和负数；零不改变余额，负数按所选交易类型的代数反方向影响余额
- 快速模板与周期交易规则；快速模板管理页必须支持通过右侧手柄拖动全部模板，持久保存完整顺序，并始终把排序前 5 个用于闪电快捷面板。新建模板必须完成“填写交易→确认模板名称→保存并返回列表”的连续流程，关闭命名框时不得因输入控件仍在退场而崩溃。新建周期规则后必须立即生成未来 3 个完整日历月的预计交易；规则管理页仍可主动补生成未来 1–12 个月，未来生成项一律为 `planned`，不得提前改变真实余额
- 分类预算、滚存、计划占用和超支提示
- 分类预算以“生效月份”形成连续规则：某类别的规则从该月起沿用，直到更晚月份出现同类别新规则。保存新月份金额不得覆盖或删除旧规则；例如 4 月 MYR 200 适用于 4–7 月，8 月 MYR 400 适用于 8 月及以后。
- 投资/退休账户快照、净资产与未来现金流；总览支持未来 7、30、60、90 天预测窗口，交易页可浏览未来月份的预计记录
- 账户页必须提供可发现的资产目标入口和独立管理界面；用户可新增、编辑、删除目标，并查看当前总资产、历史趋势、进度、剩余金额与首次达成日期。目标口径只汇总现金、投资、退休等资产分组，不扣除信用卡和贷款等 `ReportGroup.credit` 负债。
- 报表的收入、支出、结余、趋势、分类分析和历史平均必须采用实际现金口径：只统计现金类账户的真实流入/流出，排除 `planned`。信用卡消费在刷卡时不计现金流出，现金还信用卡或贷款时按现金账户整笔付款计入现金流出，现金账户之间转账净额为零。
- 信用卡额度、结算日、还款日、本期账单和未出账展示
- 贷款账户自动计算等额本息、等额本金和平息贷款的完整还款计划，并拆分每期本金、利息和剩余本金
- 账户页的“统计截止”必须是可操作的月份选择器；月份范围从账本中最早的交易、资产快照或贷款追踪月份连续列到当前月，不提供未来月份。选择历史月份后，账户分组汇总和账户行统一按该月月末计算，进入普通、投资、信用卡或贷款详情时继续沿用同一截止日期并进入只读历史模式；用户可明确返回本月。
- JSON v3 完整备份、v1/v2/v3 导入、CSV 与外部 AI 分析
- 深海主题、六个新版主页面及 29 张确认截图对应的详情/编辑流程

## 信用卡验收规则

- 结算日和还款日存放在信用卡账户，不写入每笔交易。
- 信用卡消费只保存并使用实际发生日期；账单归属由发生日期和账户级结算日推导，不允许旧版单笔结算日期覆盖发生日期。
- 日期允许 1–31；短月份自动使用月末。
- 还款日取结算日之后第一次出现的配置日期。
- 本期账单周期从“上一个结算日的次日”开始，到最近一个不晚于今天的结算日结束；未出账周期从该结算日次日开始，到下一个结算日结束。筛选必须同时比较年、月、日，不能只比较日号。
- 未完成设置的旧卡不在迁移中猜测资料；账单计算保持估算提示。进入编辑页时提供额度 10,000、结算日 12、还款日 28 的建议值，只有保存后才写入。
- 信用卡还款记录为同币种现金账户转入信用卡的转账，不计入消费发生口径，但按完整还款金额计入实际现金流出。创建还款必须使用与贷款一致的“选择还款账户 → 确认金额”专用流程；修改既有账单交易继续使用 `TransactionComposerPage`。
- 信用卡作为转出账户的转账属于该卡新增负债，必须按发生日期计入转出卡账单并显示在账单明细；若目标也是信用账户，该笔转入只作为目标卡还款/负债减少，不得再次计为目标卡消费。
- 信用卡状态必须先判断剩余账单金额，再解释日期：只有本期仍有应还金额且还款日已过才能显示“逾期未还”；本期已还清时不得显示“已过期”，应显示“本期已还清”，并在存在未出账消费时改为展示“下期已使用额度”。无账单消费、尚未出账、今日到期、待还款、逾期未还、已还清、无欠款和账期待设置均有独立文案。
- 信用卡“当前欠款”和“额度使用”按承诺负债计算：所有 `actual`/`settled` 记录即使发生日期在未来也计入，以覆盖已经锁定额度的分期；所有 `planned` 记录无论日期均不计入。该口径不得替代按今天和账期边界计算的本期账单、未出账与还款提醒。
- 信用卡详情的“查看账单”必须列出可由现有交易回溯的账单月份；每项显示完整账期、还款日和账单金额。选择历史月份后，主金额、时间线和交易明细切换到对应账期，并可返回本期。历史账单归属仍按完整年月日及账户结算日计算。
- 投资与退休账户详情必须提供显眼的“录入/更新当前市值”入口；入口锁定当前账户，投入与取出继续来自交易记录，市值更新写入新的资产快照。
- 新增、编辑或删除资产快照后，账户当前余额不得丢失快照之后的实际收入/支出，删除唯一快照也不得把余额归零，而应按期初余额与实际交易重建；回溯日期快照不得覆盖较新快照的余额。系统无法可靠确定余额的快照操作必须明确拒绝并说明原因，不得静默写入可能错误的余额。这类操作是：在已有实际转账/调整的账户中，删除最新快照（仍有较早快照），或编辑后改变了哪张是最新快照。
- 账户在快照之后某日的余额应为快照市值加快照之后到该日的实际收入/支出，并扣回该日之后已并入快照市值的转账/调整；该日之后的收入/支出不得扣减。查询首张快照之前的日期时，余额与成本只能来自此前账本，不得读取未来快照。
- 投资未实现盈亏必须以同一截止日的总市值减剩余成本计算；首张快照以前的取出已包含在成本基线内，不可重复扣减。报表跨币种汇总须先按账户币种换算为主币种。

## 贷款账户验收规则

- 新贷款账户必须填写合同贷款金额、非负年利率、贷款年限、合同开始日、开始记账日期、每月还款日和还款方式；年限以年输入，但必须能换算为完整月份，支持 1–1200 期。开始记账日期不得早于合同开始日。
- 还款方式支持 `equalInstallment`（等额本息）、`equalPrincipal`（等额本金）和 `flatRate`（平息贷款）。等额本息与平息贷款可选填银行核定的常规月供；核定月供必须大于当期利息且不能在合同期满前清偿，尾期自动调整并结清剩余本金与合同利息。等额本金不接受固定核定月供。
- 完整还款计划是由账户条件实时派生的只读计划，不批量写入 `planned` 交易。每期必须展示期数、到期日、月供、本金、利息及剩余本金。
- 可选开始记账余额必须大于零且不超过合同贷款金额，缺省时等于合同金额。余额小于合同金额表示中途建账；系统不得为以前已还的期数生成交易，只生成从开始记账日期之后尚待记录的计划。
- 首个待记录期数在开始记账日期的下一个自然月，到期日使用账户还款日；当月没有 29–31 日时夹取为月末。
- 贷款以开始记账余额的负数初始化账户余额。编辑开始余额时保留建账后实际本金还款形成的差额和既有交易，不回填历史还款。
- 记录某期还款时，必须选择与贷款同币种的现金类账户；系统写入一笔“贷款月供”转账，其来源金额为完整月供、目标入账金额为当期本金。现金账户减少完整月供，贷款余额只减少本金，利息为两者差额，不得把本金金额显示成月供。
- 新建完整贷款账户后必须主动询问是否生成预计还款；用户选择同币种现金账户并确认后，系统为所有尚未记录期数各生成一笔 `planned` 完整月供。贷款详情必须提供“生成/补齐全部预计交易”入口，重复执行不得重复生成已有期数。
- 预计贷款交易不改变当前账户余额；记录某期实际还款时，系统先移除该期同一来源账户与到期日的旧预计组合，再写入实际完整月供。旧版生成的“本金转账 + 利息支出”预计组合在打开贷款详情时自动合并成一笔月供记录。
- 删除贷款月供后必须立即撤销现金与贷款余额影响，并让该期重新成为下一期待记录期。删除旧版本金或利息中的任一笔时，系统必须识别同来源、同状态、同日期和同期号的互补记录并原子删除整期。预计交易按钮必须显示精确缺口，例如总计划 58 期且已有 19 期时显示“补齐 39 期预计交易”；缺口为零时显示“预计交易已补齐”并禁用。
- 已记录期数由转入贷款账户且描述为 `贷款本金 #<期数>` 的实际转账识别；重复记录前必须推进到下一未记录期。手工修改或删除关联交易会使计划状态按当前账本重新派生。
- 当前实现不自动处理浮动利率重定价、手续费、罚息、提前还款重算、部分还款或不同币种还款；这些属于已知限制，不能在界面暗示已自动覆盖。

## 交易删除验收规则

- 交易主列表支持长按进入选择模式；选择模式下点击可继续选择或取消选择，并可一次选择当前筛选结果中的全部记录。
- 删除一笔或多笔交易前必须显示确认提示；确认后删除记录并撤销这些记录对来源账户和目标账户余额的影响。
- 编辑已有交易的完整页面必须提供“删除交易”入口；点击后显示不可撤销及余额恢复提示，只有再次确认才执行删除。取消确认后继续留在编辑页面。
- 批量删除必须具备原子性：只要任一所选记录已不存在，整批删除和余额回滚都不得生效。
- 删除成功后必须通过 `financeRepositoryProvider` 发布最新快照，交易列表、现金流和账户余额在当前界面实时刷新。
- 删除已由周期规则生成的交易不会删除周期规则本身；规则管理仍是独立操作。

## 交易状态与时间口径

- “实际”口径只包含 `actual`/`settled`，排除 `planned`；“预计”口径只包含 `planned`。
- 交易主页面默认使用“已发生”计算口径；用户选择“包含预计”后，收入、支出、净现金流和交易列表必须统一使用 `actual`/`settled` 加 `planned`，不得把第二个选项实现成只显示预计。进入未来月份时默认启用“包含预计”，但仍保留该月份已经确定的实际记录。
- 交易主页面提供三种互不混用的分析口径：“实际消费”按交易发生日汇总收入与支出，转账不算消费；本月及未来月份的“实际现金”以“需准备现金”为副标题，显示已知现金流出加尚未覆盖的到期信用卡/贷款；“信用/贷款”显示全部信用/分期账户当前已锁定负债，并以所选月份的新增承诺和偿还抵扣解释变化。历史月份的中间卡显示该月实际现金支出。
- 三种分析口径只改变顶部卡片和解释指标，不隐藏交易明细；账户、类型、类别筛选必须同时作用于交易列表、实际消费和信用/贷款口径。“实际现金”的需准备总额是全月指标，只跟随月份与“已发生/包含预计”，不受明细筛选缩小，并在选中时明确提示这一边界。“包含预计”开启时，实际消费与资金需求加入所选月份 `planned`；信用/贷款卡片在当前负债上仅加入所选月份预计信用变动，不得把预计交易写入真实欠款。
- 未来月份的“现金收付”和现金流预测必须按现金账户整笔增减计算。结构化贷款月供的 `amount` 是现金流出金额，不能用 `toAmount` 本金或两者差额利息替代。
- 本月及未来月份的中间口径卡必须命名为“实际现金”，并以“需准备现金”为选中副标题：金额以当前“已发生/包含预计”范围内的已知现金流出为基础，加上该月到期但尚未由还款交易覆盖的信用卡账单与贷款月供。已存在于现金流出的实际或预计还款只标示为“已包含”，不得再次相加；转入对应贷款账户的普通手工转账也必须视为覆盖，不强制要求系统生成的期号文案。选中后使用原有两项解释区显示“已知流出/尚未安排”，再用一行紧凑说明显示到期信用、到期贷款和已包含金额；不得另建独立大卡。
- 没有时间范围参数的余额、净资产、投资/退休流入和账户汇总，默认截止到当前自然月最后一天，不读取未来月份交易。
- 信用卡本期账单、未出账和还款提醒截止到今天，不读取未来日期的 `actual` 或 `planned`；当前欠款和额度使用是例外，包含全部日期的 `actual`/`settled`，排除全部 `planned`。
- 周期规则保存的是交易内容与重复条件；自动生成器只展开今天之后的日期，并统一写为 `planned`。实际发生后由用户将预计交易转为实际，规则本身不会提前改变账户余额。
- 所有显示箭头、下拉符号或启用按钮的控件必须执行真实导航、选择、保存或计算；纯信息行不得绑定空回调。未实现能力必须明确标为“计划中”并禁用。周期规则编辑必须支持交易内容、金额与账户、类别、间隔、开始日期、结束条件、启停、删除及未来 1–12 个月补生成。
- 明确的预测窗口以截至今天的实际余额为起点，再叠加窗口内的 `actual` 与 `planned`；同一未来交易只能计算一次。
- 明确选择历史或未来月份时按所选范围过滤；页面必须分别标示实际与预计，不得把预计金额混入实际金额。
- 历史账户截止只纳入截止日当日及以前的 `actual`/`settled` 记录和资产快照，排除 `planned` 及截止日之后的交易；历史详情不得显示新增、编辑、删除、还款、补生成预计交易或录入市值等写入入口。
- 类别管理的分组箭头必须真实展开或折叠对应列表；输入框、禁用计划项和只读主题预览等非导航元素不得显示误导性的右箭头。

## 未来已确定信用账单验收补充

- “查看账单”必须列出未来日期但状态为 `actual`/`settled` 的已确定账单月份，并按结算日期从近到远浏览；未来 `planned` 不得创建已确定账单或进入其金额。
- 每个未来已确定月份的还款日仍取结算日之后第一次出现的账户还款日，例如 7 月结算对应 8 月还款。
- 账单月份显示的是该期原始账单额，还款只能减少“剩余待还”，不得把已还清的历史账单金额改成零。原始账单优先按该期消费、信用卡转出、退款和调整求和；旧导入资料缺少完整消费明细时，可使用结算日至还款日之间已经明确转入该信用账户的账单还款作为已付账单额凭据。
- 用户提供银行结单并完成本地对账后，该结算日的银行账单总额是权威值，必须优先于交易推算和后续还款金额；权威值按账户和结算日保存，切换历史月份时只影响该期原始账单显示，不改变当前欠款、额度使用或交易明细。
- 每月 1 日结算的账单归属于刚结束的月份：例如 8 月 1 日结算、8 月 10 日还款的账单必须标为“7 月账单”。其他结算日同样以结算日前一天所在月份作为账单月份。
- “下期已使用额度”先按下一完整账期内的 `actual`/`settled` 消费及信用卡转出合计，再扣除本期账单清偿后确实剩余并已抵扣到该账期的还款额度；不得直接使用全历史累计余额，也不得继续展示已被超额还款抵消的毛消费。未来已确定分期只进入各自月份；缺少转入还款凭据的旧资料仍以账期流水为准，不能因不完整余额把 7 月 RM313.29 错算成 RM151.96。
